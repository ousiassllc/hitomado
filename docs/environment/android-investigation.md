# Android 版の試作と調査の結果（#81）

> 関連: [Android ビルド](android.md) / [環境構築](setup.md) / [アーキテクチャ設計](../architecture/overview.md)

Issue #81 は、Wails v3 の Android 対応（試験的）で Hitomado の Android 版がどこまで動くかを、試作で確かめる調査だった。本書は、その結果表・バックグラウンド同期の案・本実装の Issue 案を 1 か所にまとめる。**各項目の細かい設計・手順・確認の範囲は [Android ビルド](android.md) の節に書いてあり、本書は要約と案内**である。

- 試作のブランチは `proto/android-81`（参考として残す。直接は使わない）。本実装は試作から土台を取り込み（#82）、以降の Issue（#83〜#90）で作り込んだ。
- **Android 版は Releases の検証用 APK として配る。Google Play には出さない**（[Android ビルド §8](android.md#8-ciリリースciymlreleaseyml)・#91）。
- **実機（arm64）での確認はまだ行っていない**。エミュレーター（x86_64・API 35・KVM なしのソフトウェア実行）と、ホストでのテストの範囲だけである。表の「実機」の欄はその区別を示す。

## 1. ビルドと起動（やること 1）

| 項目 | 結果 |
|------|------|
| Android 版のビルド | **通る**。`task android:package`（release APK）・`android:bundle:fat`（AAB。arm64＋x86_64）が通り、`android:verify` が manifest・署名・権限を検査する。PR の CI の `android` ジョブが毎回 APK と AAB を作る（[§8](android.md#8-ciリリースciymlreleaseyml)） |
| エミュレーターでの起動 | **起動する**（x86_64・API 35）。ただし x86_64 は `modernc.org/libc` のパッチなしでは SQLite の最初のファイル操作で落ちる（次の表） |
| エミュレーターで一覧表示まで | **未確認**。KVM なしの環境で WebView のレンダラが落ち続け、一覧まで到達できなかった（[§17.6](android.md#176-確認の状況2026-11-04)） |
| 実機（arm64） | **未確認**（端末が無い） |

試作で分かったこと（本実装で直した）:

- Go の `os.UserConfigDir()` が Android では使えない（`HOME` が `/`）ので、データの置き場所は `getFilesDir()` 配下にした（`datadir_android.go`）。
- Linux 用の通知サービス（D-Bus）は Android で起動に失敗するので、Android では登録しない（`notifsvc_android.go`）。
- WebView のレンダラが落ちるとアプリのプロセスごと終了する（Wails 3.1.0 のテンプレートは `onRenderProcessGone` を実装していない）。作り直す処理を足した（[§17.1](android.md#171-webview-のレンダラが落ちたときonrenderprocessgone)）。

## 2. 「未確認」だった項目の結果（やること 2）

| 項目 | 結果 | 直し方・現状 | 実機 |
|------|------|--------------|------|
| 保存ダイアログ（`SaveFile`）・フォルダ選択 | **そのままでは使えない**（Wails の Android では保存・フォルダ選択はエラーを返す） | 添付とログの保存は Storage Access Framework（`ACTION_CREATE_DOCUMENT`）と FileProvider に置き換えた。フォルダを開く導線は Android に無いので「ログを書き出す」を案内する（#85、[§13](android.md#13-添付の保存ログの書き出しファイルを開く85)） | 未確認 |
| システムトレイ（未読バッジ） | **何もしない**（Wails の Android ではトレイの呼び出しが無効） | トレイを作らない。未読は通知で知らせる（#89、#88） | — |
| 資格情報（`go-keyring`） | **動かない**（Secret Service〈D-Bus〉が無い。試作のプローブで確認） | EncryptedSharedPreferences（鍵は Android Keystore）に置き換えた。鍵が失われたときの復旧と、Activity なしで読む経路も実装（#84、[§11](android.md#11-資格情報の保管84)） | 自動テストと x86_64 エミュレーターまで。実機は未確認 |
| Google OAuth のループバック | **試作では、アプリ内の待受へ `adb shell` の別プロセスから GET して完了まで動いた**。ブラウザからの GET と本物の Google は未確認 | `127.0.0.1` のループバック＋PKCE＋`state` のまま、デスクトップ アプリ種別のクライアントで使う。Android／Web 種別とカスタムスキームは Google が使えなくしているので採らない。ブラウザに出ている間にプロセスが止められたら、次の起動で「やり直し」と案内する（#86、[§14](android.md#14-google-oauth-のリダイレクト方式86)） | 未確認 |
| `modernc.org/sqlite` | **arm64 は問題の対象外（静的に確認）、x86_64 は落ちる**。x86_64 では旧式のシステムコール番号を Android の seccomp が拒否し `SIGSYS` で落ちる（上流に同じ問題の報告があるが未修正） | x86_64 は `modernc.org/libc` に小さなパッチを android/amd64 のビルドにだけ当てる（`go.mod` は変えない）。x86_64 エミュレーターでは DB の作成・マイグレーション・整合性まで確認した（#83、[§12](android.md#12-moderncorglibc-の-androidamd64-問題83)） | **arm64 の実機は未確認** |
| `internal/mcpserver` | **Android では持たない**と決めた | 待受けず、バインディングにも出さず、設定画面にも出さない。機能の有無は `internal/capability` で持つ（#89、[§10](android.md#10-android-で動かさない機能)） | — |

## 3. バックグラウンドでの受信同期と新着通知（やること 3）

採用した方式（#88、詳細は [§15](android.md#15-バックグラウンド同期と新着通知88)）:

- 前面にいる間は今の 60 秒ループ。閉じている間は **WorkManager の定期実行（15 分間隔。ネットワーク接続が条件）** が、Go の「1 回だけ同期して新着を返す」関数（`internal/headless`）を呼ぶ。Worker は Activity もアプリ本体も無いプロセスで動く。
- 通知は Java の `NotificationManager`。タップでそのスレッドを開く。再認証が要るときは「再接続が必要」の通知を出す。

| 案 | 判断 | 理由 |
|----|------|------|
| **WorkManager の定期実行（採用）** | 採る | サーバーが要らない。OS が実行を管理する（Doze・省電力に従う） |
| Gmail の Pub/Sub 通知＋FCM | 採らない | 公開者サーバーが要り、「サーバーを持たない」方針（[非機能要件](../requirements/non-functional.md)）と矛盾する |
| 前面サービス（`dataSync`）で常時接続 | 採らない | 常時表示の通知が要る。targetSdk 35 以降は `dataSync` に時間の上限がある。Play の審査の対象にもなる |
| 15 分より短い間隔 | できない | `PeriodicWorkRequest` の下限が 15 分 |

限界: 新着の通知は**最大 15 分遅れる**。Doze・待機バケット・メーカー独自の省電力で、さらに遅れる（利用者向けの案内は機能要件 F-10）。**エミュレーターで確認したのは、ジョブの登録・Activity なしでの Worker から Go までの実行・「再接続が必要」の通知**まで。実機での新着の通知、通知のタップでスレッドが開くこと、通知の許可のダイアログは未確認（[§15.9](android.md#159-確認の状況)）。
