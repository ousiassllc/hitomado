# 非機能要件

> 関連: [プロジェクト概要](../overview.md) / [機能要件](functional.md) / [アーキテクチャ設計](../architecture/overview.md)

数値の「目安」は、実測で乖離が大きければ見直す暫定値。「必須」は満たさなければリリースしない。

## 1. セキュリティ

| ID | 区分 | 要件 |
|----|------|------|
| NF-S01 | 必須 | OAuth のリフレッシュトークン、OAuth クライアントの Client Secret、AI の API キー、ChatGPT ログインのトークン（アクセス・リフレッシュ・ID）は **OS の資格情報ストア（Windows 資格情報マネージャー）** に保存する。Android では Android Keystore の鍵で暗号化した EncryptedSharedPreferences にだけ保存し、バックアップ・端末間移行の対象にしない（Keystore の鍵が失われて読めなくなったときは、保存済みの値を破棄してアカウントを「要再接続」にする）。SQLite・設定ファイル・ログ（logcat を含む）に平文で保存しない |
| NF-S02 | 必須 | Gmail スコープは `gmail.modify` のみ（加えて `openid email profile`）。`mail.google.com`（完全削除）や連絡先スコープは要求しない |
| NF-S03 | 必須 | OAuth は認可コードフロー＋PKCE、リダイレクトは `127.0.0.1` のループバック（一時ポート）。`state` を検証する。待受は認可完了またはタイムアウト（5 分）で閉じる。Android も同じ方式（[Android ビルド §14](../environment/android.md#14-google-oauth-のリダイレクト方式86)）で、認可の途中でプロセスが止められたことの検出のために資格情報ストアへ残すのは時刻だけ（`state`・PKCE verifier は残さない） |
| NF-S04 | 必須 | HTML メールは DOMPurify 等でサニタイズした上、`sandbox` 属性付き iframe（`srcdoc`）内に表示する。`sandbox` は **`allow-scripts`・`allow-forms`・`allow-popups`・`allow-top-navigation` を付けない**（メール内スクリプトは実行されない）。ホストが高さ計測とリンク捕捉をするため `allow-same-origin` のみ付ける（スクリプト実行が不可能なことが前提。[コンポーネント設計 §3.8](../components/overview.md)）。iframe 内の CSP は `default-src 'none'`。スクリプト・フォーム・外部 CSS・iframe・`<base>` は除去する |
| NF-S05 | 必須 | リモート画像（`http(s)` の `img`・CSS `url()`）はデフォルトでブロックする（[F-03](functional.md#f-03-スレッド閲覧)） |
| NF-S06 | 必須 | WebView の Content Security Policy を厳格に設定し、外部オリジンの読み込み（スクリプト・接続）を許可しない。外部通信はすべて Go バックエンド経由で行う |
| NF-S07 | 必須 | リンクを開く際は `http`／`https`／`mailto` のみ許可する。`file:`・`javascript:` 等は拒否する |
| NF-S08 | 必須 | ローカル DB には**メッセージ本文・添付を保存しない**。保存するのはヘッダ由来のメタデータ（差出人・宛先・件名・日時）、スニペット、ラベル、同期状態、連絡先候補のみ |
| NF-S09 | 必須 | 本文・添付は開いたときに取得し、メモリ上の LRU（直近 50 スレッド目安）にのみ保持する。添付のダウンロードは利用者が選んだ保存先にのみ書き、一時ファイルを作る場合は終了時に削除する。保存したファイルには Windows の Mark-of-the-Web（`Zone.Identifier` の `ZoneId=3`）を付け、開くときに SmartScreen／保護ビューが働くようにする（ADS 非対応のボリュームで付けられなくても保存は成功させ、ログには理由のみ残す） |
| NF-S10 | 必須 | ログ（ファイル・標準出力）にトークン・API キー・パスワード・OAuth 情報・メール本文・件名・宛先アドレスを出力しない。アカウントはアカウント ID で記録する。ログの組み立て（`internal/logging`）が、書き込む前にすべての値を伏せる（秘密・メール内容のキーの値は丸ごと、文字列に混ざったトークン・アドレスはパターンで）。panic の値・フロントから届くエラーも同じ処理を通る。テストで確かめる。形式・場所・保持は [MCP 連携とログ](../mcp.md#ログ) |
| NF-S11 | 必須 | 送信元が受信アカウント以外になる返信・転送は、UI だけでなくバインディング（Go 側）でも拒否する（[バインディング仕様](../api/endpoints.md)） |
| NF-S13 | 必須 | 内蔵 MCP サーバーは**既定オフ**で、設定でオンにしたときだけ待ち受ける。オンでも、アプリが作る Bearer トークンが無い・合わない接続はすべて `401` で拒否する（トークン未発行のときも拒否）。待ち受けは既定で `127.0.0.1` のみ。loopback 以外（tailnet など）は設定で明示的に許可したときだけ。トークンは資格情報ストアに保存し（NF-S01）、再発行・無効化できる |
| NF-S14 | 必須 | MCP で公開する機能は、状態・ログ・メールの読み取りと返信下書きの作成だけ。**送信するツールを作らない**（`PrepareSend`／`Send` に相当する機能を MCP の機能一覧に含めない）。送信は必ず人がアプリで行う。MCP が作る下書きの送信元は受信アカウントに固定する（NF-S11 と同じ規則） |
| NF-S15 | 必須 | MCP のツール呼び出しはログに記録する（いつ・どのツール・成否）。引数・本文・結果は記録しない（NF-S10） |
| NF-S12 | 推奨 | ローカル DB（件名・スニペットを含む）は暗号化しない。ユーザープロファイル配下（`%APPDATA%\Hitomado`）に置き、README で BitLocker 等のディスク暗号化を案内する |

## 2. プライバシー・外部通信

- MCP サーバーは待ち受け（受信）のみで、外部へ通信しない。既定はオフ（NF-S13）

- 外部通信先は次のものに限定する。**公開者のサーバーへは一切通信しない**。テレメトリ・クラッシュレポートの自動送信は行わない。ただし、利用者がメッセージ単位で「画像を表示」を押したときに限り、メール本文が参照するリモート画像を WebView が HTTPS で取得する（取得先はメール送信者が指定したホスト。[F-03](functional.md#f-03-スレッド閲覧)）

| 通信先 | 用途 | 送信される内容 |
|--------|------|----------------|
| `accounts.google.com`、`oauth2.googleapis.com`、`openidconnect.googleapis.com` | OAuth 認可・トークン更新・アドレス取得 | OAuth プロトコルに必要な情報 |
| `gmail.googleapis.com` | メールの取得・操作・送信、署名の取得（`users.settings.sendAs.get`。F-07。「Gmail から取得」を押したときだけ） | 各操作の内容 |
| AI プロバイダ（利用者が設定したもの） | AI 下書き（F-08）、スレッドの AI 要約（F-17）、スレッドへの AI 質問（F-18）、モデル一覧の取得 | 下書き: スレッド本文の一部・表示名・署名（ボタン押下時のみ）。要約: 開いているスレッドの全メッセージの本文・差出人・日時・添付のファイル名とサイズ（ボタン押下時のみ。合計 40,000 文字を目安。添付の中身・画像は送らない）。質問: 要約と同じスレッドの内容に加えて、利用者が入力した質問と、そのスレッドで今までに交わした質問・回答（質問を送る操作のときのみ。会話は最新 10 往復・合計 20,000 文字まで）。モデル一覧の取得は API キー（またはログインのトークン）だけで、メール内容は含めない。同意前の送信先には送らない |
| `auth.openai.com` | ChatGPT プランのログイン・トークン更新・失効（Sign in with ChatGPT。利用者が選んだときのみ） | OAuth プロトコルに必要な情報（クライアント ID・ホスト ID・認可コード・トークン）。パスワード・Cookie は Hitomado を通らない |
| `api.openai.com`（ChatGPT プラン） | AI 下書き・スレッドの AI 要約・質問（Responses API）・モデル一覧 | AI プロバイダと同じ内容。アクセストークンで認証する |
| `api.github.com` | 新バージョン確認（NF-D03） | リクエスト（IP・User-Agent）のみ。メール・アカウント情報は含めない |
| `github.com`、`release-assets.githubusercontent.com` | Windows 版の自動アップデート（NF-D03）: Release の添付ファイル（インストーラー・`SHA256SUMS.txt`）のダウンロード。`github.com` の `releases/download/...` が配信元（`release-assets.githubusercontent.com`。以前は `objects.githubusercontent.com`）へ 302 でリダイレクトする。許可するのは `github.com` と `*.githubusercontent.com` の HTTPS だけ。設定でオフにできる | リクエスト（IP・User-Agent）のみ。メール・アカウント情報は含めない |

- AI 下書きは、初回利用時に「スレッドの内容が選択した AI プロバイダへ送信される」ことを表示し、同意を保存する。同意前は生成しない。同意前は、モデル一覧の取得も送信先へ送らない。同意は、設定を保存する前にプロバイダ・送信先を選んだ時点でも取る（#105）
- AI 下書きの「AI への指示」（F-08。#109）も、スレッドの内容と同じ送信先へ送られる内容として扱い、新しい同意は取らない（同意の画面の説明に「入力した指示も送信される」を載せる）。指示の本文はログ・エラー文面・DB に残さない（NF-S10）
- スレッドの AI 要約（F-17。#206）も、スレッドの内容と同じ送信先へ送られる内容として扱い、新しい同意は取らない（同意の画面の説明に「要約・質問ではスレッドの全メッセージ（上限あり）が送信される」を載せる）。送る量は下書きより多い（直近 5 メッセージ・20,000 文字ではなく全メッセージ・40,000 文字が目安）が、送信先・内容の種類は同じである。要約の本文・スレッドの内容はログ・エラー文面・DB に残さない（NF-S10）
- スレッドへの AI 質問（F-18。#207）も同じ送信先へ送られる内容として扱い、新しい同意は取らない（同意の画面の説明に「入力した質問と、それまでの回答も送信される」を足す）。質問・回答・会話は、開いているスレッドの間だけフロントのメモリに持ち、ログ・エラー文面・DB・`localStorage` に残さない（NF-S10）。AI の回答はスレッドの内容から作られるため、Go は回答をログに出さない。AI は答えるだけで、メールの送信・スレッドの操作・下書きの作成は行わない（送信は人が行う）
- Gmail の署名の取得（F-07。#110）は、既存の `gmail.modify` スコープで読めるため（`users.settings.sendAs.get` は `gmail.modify` で許可される）、スコープを追加せず再接続も求めない（NF-S02 のまま）。署名の本文は利用者のアカウント情報としてログ・エラー文面に残さない（NF-S10）
- AI プロバイダが OpenAI 互換のエンドポイントの場合、Base URL は利用者が指定する。送信先は設定画面に常に表示する
- Base URL は `https://` を原則とする。`http://` はホストが `localhost`／`127.0.0.1`／`::1`（ローカルの LLM サーバー）に完全一致するときだけ許可し、それ以外の `http://`（平文でのスレッド内容の送信）は拒否する。認証情報（`user:pass@`）・クエリ・フラグメントを含む URL も拒否する。保存済みの設定がこれに反する場合は、接続せずにエラーとし、同意も無効として扱う
- AI 送信の同意は「プロバイダ＋送信先（Base URL の scheme とホスト）」ごとに保存する。送信先が変わる（Base URL のホスト変更・`https`→`http` など）と同意は無効になり、再度の同意が必要になる（API キーは維持する）
- **ChatGPT プラン（Sign in with ChatGPT）**: OpenAI の公式ドキュメントと規約に従う。トークンは公式のサインインフロー（システムブラウザでの OpenAI の画面。PKCE・state・nonce・127.0.0.1 の一時ポートへのリダイレクト）だけで取得し、パスワードもセッション Cookie も求めない。Codex CLI など他アプリの認証情報は読まない・使わない。Hitomado 自身の名前（`Hitomado`）で登録し、OpenAI やほかのアプリを名乗らない。プラン枠・トークンを他者と共有しない。アクセス・リフレッシュ・ID トークンは資格情報ストアにだけ保存し、ログ・エラー文面・UI・MCP に出さない（NF-S10）。MCP からログイン・ログアウト・トークンの操作はできない（[MCP](../mcp.md)）
- AI プロバイダの応答が 3xx（リダイレクト）のときは追従せず、失敗（`AI_FAILED`）として扱う。同意した送信先（scheme＋ホスト）以外へスレッド内容が再送されることを防ぐため。Base URL にはリダイレクト後の最終的な URL を指定する（末尾スラッシュの 301 などを返す環境では、正しい URL に直す）

| ID | 区分 | 要件（目安） |
|----|------|--------------|
| NF-P01 | 目安 | 起動から受信箱（キャッシュ表示）まで 3 秒以内（8 アカウント、キャッシュ済み） |
| NF-P02 | 目安 | スレッドを開いてから本文表示まで 1.5 秒以内（回線良好、未キャッシュ時） |
| NF-P03 | 目安 | 差分同期 1 周期（8 アカウント並列・変更なし）が 10 秒以内に完了する |
| NF-P04 | 目安 | 受信箱リストは 2,000 行をスクロールしても滑らか（仮想スクロール） |
| NF-P05 | 目安 | アイドル時のメモリ使用量 400MB 以下、CPU 使用率はほぼ 0%（同期周期以外） |

## 4. 同期

- 方式: Gmail の `users.history.list` による差分ポーリング。**60 秒間隔**、アカウント並列。公開者サーバーを要する Pub/Sub 通知は使わない
- 初回同期: 各アカウントの `INBOX` の最新 200 スレッドをメタデータのみ取得する。以降は一覧の末尾の「さらに読み込む」ボタンで追加取得する
- `historyId` が失効（404）した場合は当該アカウントの `INBOX` を再取得する（リセット同期）。その場合、新着通知は出さない
- ウィンドウ非表示（トレイ格納中）でも同間隔を維持する。手動更新はいつでも可能（直近の手動更新から 5 秒未満は無視）
- Gmail API の割当（1 ユーザーあたり 250 クォータユニット/秒）を超えないよう、アカウントごとにレートリミッタを置く。429／5xx は指数バックオフ（初回 1 秒、上限 60 秒、ジッタ付き）で再試行する。ただし二重実行になり得る `messages.send` と `drafts.create` は、二重送信・重複作成を避けるため 5xx を再試行しない（429 は再試行する）
- アカウントごとの同期状態（`historyId`、最終同期時刻、エラー）を保持し、UI に反映する
- **Android 版のバックグラウンド同期**: アプリが前面にいる間は上の 60 秒間隔。アプリを閉じている間は OS の定期実行（WorkManager。**15 分間隔**＝OS の下限・ネットワーク接続が条件）が、同じ差分同期を 1 回だけ実行して新着を通知する（Android は前面にいないアプリを止めるため、常駐しない）。**Pub/Sub・FCM など公開者サーバーを要する方式は使わない**。前面サービスは使わない（常時表示の通知・Android 15 以降の `dataSync` の時間上限・Play の審査を避ける）。同じプロセスでアプリ本体が動いているときは、Worker は別に同期せずアプリ本体の同期に任せる（二重通知を避ける。[Android ビルド §15](../environment/android.md#15-バックグラウンド同期と新着通知88)）

## 5. 可用性・信頼性

- アカウント単位で故障を隔離する（NF-P06）。トークン失効は当該アカウントのみ「要再接続」（[F-01](functional.md#f-01-アカウント接続byo-oauth)）
- ネットワーク断では取得済みのキャッシュ表示を維持し、書き込み系操作は失敗として扱う（送信キューは持たない）
- SQLite は WAL モードで使用し、強制終了時にも破損しない。スキーマ変更はマイグレーションで行い、失敗時は起動を中止してエラーを表示する
- 下書きは編集停止後に自動保存する（[F-12](functional.md#f-12-下書き保存)）。異常終了時に失う編集は直近の数秒分までとする
- 多重起動は禁止する（2 つ目の起動は既存ウィンドウを前面に出して終了）。Android 版では多重起動の防止をアプリで行わない（起動の管理は OS の任せ。[Android ビルド §10](../environment/android.md#10-android-で動かさない機能)）
- Android 版では、WebView のレンダラが落ちて（クラッシュ・メモリ不足による OS の終了）もアプリ全体は終了しない。落ちた WebView を作り直して読み直し、直近 5 分に 3 回を超えたらエラー画面で再起動を案内する。作り直しで消えるのは画面側の状態で、保存済みの下書き（編集停止後の自動保存。Gmail 側）は残る。初回の画面の読み込みが遅くて失敗したときも、上限つきで読み直す（[Android ビルド §17](../environment/android.md#17-実機エミュレーターでの-e2e-webview-のクラッシュ対策性能90)）

## 6. スケーラビリティ・容量

- 対象規模: 8 アカウント（目安）。上限は 20 アカウント（性能目安を満たす範囲）
- ローカル DB はアカウントあたり数千スレッド（メタデータ＋スニペット）で数十 MB 以内に収まる想定。古いスレッドの削除条件（`INBOX` を外れてから 90 日経過したもの）を設け、肥大化を防ぐ

## 7. 互換性・動作環境

- OS: Windows 10（1809 以降）／Windows 11、x64。ARM64 の Windows 11 は x64 エミュレーションで x64 版を動かす（ARM64 版のビルド・インストーラーは作らない。ARM64 の Windows 10 は x64 エミュレーションが無いため対象外。[環境構築 §4.3](../environment/setup.md)）
- OS（Android）: Android 12（API 31）以上（`minSdk` 31）。それより古い端末にはインストールできない
- WebView2 ランタイムが必要。未導入環境ではインストーラ／README で案内する
- 画面（Windows）: 最小ウィンドウ幅 960px、3 ペイン。DPI スケーリング 100〜200% で崩れないこと
- 画面（Android）: 最小幅の制限なし。幅 360px（スマホ）から使えること（640px 未満は 1 画面ずつ、640px 以上 1024px 未満は 2 ペイン、1024px 以上は 3 ペイン。[機能要件 §5.1](functional.md#51-androidスマホの画面)）。タップ領域は 44px 以上
- 言語: UI は日本語のみ（v0）。文字列は定数・メッセージファイルに集約し、将来の多言語化を妨げない

## 9. 外部サービスの制約（README で案内する）

- OAuth 同意画面の公開状態: **External かつ「テスト」のままだとリフレッシュトークンが 7 日で失効する**。利用者には「本番環境（未確認アプリ）」へ切り替える手順、または Workspace の「内部」アプリを使う手順を README で示す
- 「未確認アプリ」警告が認可時に出る。100 ユーザー上限は個人利用では問題にならない
- Workspace の管理者が外部アプリのアクセスを制限している場合は、管理者の許可（API 制御）が必要
- Gmail API の割当と制限（1 日あたり、ユーザーあたり）に従う

## 10. 保守性・テスト

- Gmail クライアント・AI クライアント・資格情報ストア・時計はインターフェース越しに注入し、モック／フェイクでテスト可能にする
- 次のロジックは単体テストを必須とする: 返信宛先の決定（返信・全員に返信・転送、自アドレス除外）、MIME／ヘッダ生成、送信元の強制、署名挿入、`history` 差分の適用、HTML サニタイズ
- CI（GitHub Actions）で Go のテスト・vet・lint、フロントエンドの型チェック・lint・ビルド、Windows ビルドを実行する
- ライセンス: AGPL-3.0。依存ライブラリのライセンス互換性を確認する

## 11. アクセシビリティ

- アカウントの識別は色だけに依存しない（アカウント名チップ・アドレスを併記する）
- 主要操作（受信箱の移動、既読、アーカイブ、返信、送信確認）はキーボードで操作できる
- 色のコントラスト比は WCAG AA（4.5:1）を満たすプリセット色のみ提供する

## 12. AI

- プロバイダは抽象化（インターフェース）し、v0.1.0 では **Anthropic** と **OpenAI 互換エンドポイント**（Base URL 指定。Base URL を指定しないときの送信先は OpenAI）を実装する。加えて **ChatGPT プラン**（Sign in with ChatGPT。Responses API。**AI の設定が未保存のときの既定のプロバイダはこれ**〔#104。保存済みのプロバイダは変えない。Android も同じ〕。[バインディング仕様 §6.2](../api/endpoints.md#62-chatgpt-プランsign-in-with-chatgpt)）を選べる。プロバイダの追加・変更は [バインディング仕様 §6](../api/endpoints.md#6-aiservice) の `AIProvider` に合わせる
- API キーは利用者が入力し、NF-S01 のとおり保存する（ChatGPT プランは API キーを使わず、ログインで得たトークンを同じく保存する）。送信するコンテキストの上限は、AI 下書きでは直近 5 メッセージかつ合計 20,000 文字を目安とする。スレッドの AI 要約（F-17）・質問（F-18）はスレッド全体を読むことが目的なので、スレッドの内容は全メッセージかつ合計 40,000 文字を目安とし、超えるときは古いメッセージから外す。質問ではこれに加えて、会話（質問と回答）を最新 10 往復・合計 20,000 文字までとする
- タイムアウトは 60 秒。リクエストはユーザーが中止できる
