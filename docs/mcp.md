# MCP 連携とログ

> 関連: [プロジェクト概要](overview.md) / [非機能要件](requirements/non-functional.md)（NF-S10・NF-S13〜NF-S15） / [バインディング仕様](api/endpoints.md)（§7.1 LogService・§7.2 MCPService）

Hitomado には MCP（Model Context Protocol）サーバーを内蔵しています。エージェント（しずくなど）から MCP でつないで、アプリの状態・ログ・メールを読んだり、返信の下書きを作らせたりできます。**メールの送信は MCP からはできません。** 下書きはアプリで人が確認して、人が送信ボタンを押します。

## 守っていること

| 約束 | どう守っているか |
|------|------------------|
| 既定はオフ。オンにしてもトークン必須 | 設定が無いときは待ち受けません。オンにすると待ち受けますが、`Authorization: Bearer <トークン>` が無い・合わない接続は `401` で拒否します。トークンを発行するまでは、何を付けても拒否します |
| 読み取りと返信下書きの作成まで | 公開するツールは下の 7 つだけです。送信するツールはなく、MCP が使える機能の一覧（`mcpserver.Backend`）にも送信（`PrepareSend`／`Send`）は含まれません。確認トークンの流れ（`PrepareSend`→`Send`）はアプリの画面の中だけです |
| ログに秘密とメール本文を残さない | ログは書き込む前にすべて伏せ処理を通ります（[ログ](#ログ)） |

## つなぎ方

1. 設定 → **MCP** で「MCP サーバーを有効にする」をオンにします（既定はオフ）。
2. 「トークンを発行」を押します。**値は発行直後に 1 回だけ表示されます**（コピーして MCP クライアントに設定してください）。無くしたときは再発行します（古いトークンは使えなくなります）。
3. MCP クライアントに、設定画面に出る接続先 URL と Bearer トークンを設定します。方式は **Streamable HTTP** です。

```json
{
  "mcpServers": {
    "hitomado": {
      "type": "http",
      "url": "http://127.0.0.1:47650/mcp",
      "headers": { "Authorization": "Bearer <発行したトークン>" }
    }
  }
}
```

（設定ファイルの書式は MCP クライアントごとに違います。上は一例です。）

### 設定

| 項目 | 既定 | 内容 |
|------|------|------|
| 有効 | オフ | オンにしたときだけ待ち受けます。アプリの起動時も、保存済みの設定がオンのときだけ待ち受けます |
| 待ち受けアドレス | `127.0.0.1` | 既定は loopback のみです。`localhost`・`127.0.0.0/8`・`::1` 以外（tailnet のアドレスなど）は、次の許可をオンにしたときだけ使えます |
| ポート | `47650` | 1024〜65535。使用中のときは設定画面にエラーが出ます（アプリは起動したままです） |
| loopback 以外で待ち受ける | オフ | tailnet など別のアドレスで待ち受けるときだけオンにします。そのアドレスにつなげる機器から、**トークンを持つ人はメールを読めます**。トークンの扱いに注意してください |

設定は SQLite の `app_settings`（キー `mcp.config`）に保存します。トークンは保存しません。起動時も、保存された値を検証してから待ち受けます（DB の値が書き換えられても、許可のない非 loopback や範囲外のポートでは待ち受けません）。不正な値が入力欄に残っていても、MCP をオフにすることはできます。

### 接続の守り

- すべての接続に Bearer トークンが要ります（`401`）。トークンは定数時間で比べ、未発行・空は拒否します。
- **Host／Origin の検証**（DNS rebinding・ブラウザからの横断リクエスト対策）: `Host` が IP アドレス・`localhost`・設定した待ち受けアドレス以外（ドメイン名）なら `403`。`Origin` ヘッダがある要求は、`Host` と同じオリジンでなければ `403`（MCP クライアントは通常 `Origin` を付けません）。loopback 以外で待ち受けているときも効きます。
- **loopback 以外で待ち受けるときの注意**: 通信は暗号化されない HTTP です（トークンが平文で流れます）。tailnet のように経路が暗号化されている場合に限って使ってください。
- トークンの再発行・無効化のあと、待ち受けを作り直して開いている接続・ストリームを切ります。
- 認証で拒否した接続のログは 1 秒に 1 件までに絞ります（連打でログの履歴が押し出されないように）。

### トークン

- アプリが作る乱数（256 ビット。`hmcp_` で始まる）の Bearer トークンです。1 つだけで、再発行すると古いものは無効になります。「トークンを無効にする」で以後のすべての接続を拒否します。
- **Windows 資格情報マネージャー**（キー `hitomado/mcp_token`）に保存します。SQLite・設定・ログには入りません。画面にも発行直後の 1 回しか出しません。

## ツール

| ツール | 内容 |
|--------|------|
| `get_status` | 版、アカウントごとの同期状態（初回同期の完了・最終同期・最後のエラー）、ログの最後のエラー |
| `get_logs` | 最近のログ・エラー。`limit`（既定 100・最大 1000）・`level`（debug／info／warn／error）・`since`／`until`（RFC 3339）で絞り込み |
| `list_accounts` | 接続済みアカウント（ID・アドレス・表示名・状態）。署名や OAuth の情報は含みません |
| `list_threads` | 統合受信箱のスレッド一覧（アカウント・未読のみ・件数・カーソル） |
| `search_threads` | Gmail 検索クエリでの検索（全アカウント横断または指定） |
| `get_thread` | スレッドのメッセージを本文（プレーンテキスト）つきで取得。添付は名前・種類・サイズだけで、中身は返しません。既読にはしません |
| `create_reply_draft` | 返信（または全員に返信）の下書きを Gmail の下書きとして作成。**送信はしません** |

### 返信の下書き（`create_reply_draft`）

- 引数: `accountId`・`threadId`（必須）、`body`（必須。プレーンテキスト）、`sourceMessageId`（省略で自分以外の最新）、`replyAll`。
- **送信元は受信したアカウントに固定**されます（`accountId` のアカウントの `accounts.email` から作り、引数で変えられません）。宛先・件名（`Re:`）・`In-Reply-To`／`References`・会社ごとの署名・引用は、アプリで返信ボタンを押したときと同じ規則で決まります。本文は署名・引用の前に入ります。
- すでにそのスレッドに下書きがあるときは新しく作らず、エラーで既存の下書きの ID を知らせます（エージェントの再試行で下書きが増え続けないように）。
- 作られた下書きは、アプリのスレッド画面で開いて確認・編集し、人が送信確認ダイアログから送ります。

### 呼び出しの記録

MCP の呼び出しはログに残ります（いつ・どのツール・成否・所要時間・失敗時のエラーコード）。未知のツール名・不正な引数など、ツール本体に届かなかった呼び出しも残ります（エラーコード `PROTOCOL`）。**引数（検索語・返信本文）・結果（メール本文・宛先）は残しません。** 認証で拒否した接続は接続元アドレスとステータスだけを記録します。

## ログ

### 場所

`%APPDATA%\Hitomado\logs\hitomado.log`（他の OS では `os.UserConfigDir()` 配下の `Hitomado/logs/`）。設定 → **ログ** の「ログフォルダを開く」で開けます。「ログを書き出す」で、現行とローテーション済みのログを zip にして保存先を選んで書き出せます。

### 形式とローテーション

- JSON Lines（1 行 1 レコード）。`time`（ミリ秒・タイムゾーンのオフセットつき。例 `2026-11-03T09:00:00.123+09:00`）・`level`・`msg` のほか、すべてのレコードに `app_version`（アプリの版）と `os`（`windows/amd64` など）を付けます。
- 5 MB で切り替え、最大 5 世代（`hitomado-<時刻>.log`）、30 日を過ぎたものは削除します。

### 記録するもの

- Go 側: 同期・通知・更新確認・MCP の動作とエラー。アカウントは**アカウント ID** で記録します。panic は値とスタックトレースつきで記録します（ゴルーチンの最上位・同期の 1 周期・更新確認・Wails のバインディング呼び出し・起動処理）。
- フロント側: 未処理の例外（`error`）・Promise の reject（`unhandledrejection`）・Vue の描画エラー（`vue`）・バインディング呼び出しの失敗（`binding`。エラーコードとアカウント ID）を Go 側のログへ送って記録します（レコードは `msg: "frontend error"`、`source: "frontend"`）。画面の暴走でログが埋まらないよう、種類ごとに 1 秒に 1 件（瞬間的には 30 件まで）に絞ります（想定内の `binding` の警告が続いても、本物のエラーが捨てられないよう `binding` は別枠）。伏せ処理を先に通してから、メッセージは 1000 文字、スタックは 8000 文字で切ります。Promise の reject が `call()` の投げ直しによるもの（`binding` として報告済み）のときは、二重に報告しません。

### 記録しないもの（伏せ処理）

次のものはログに出ません。ログの組み立て（`internal/logging`）が書き込む前にすべての値を処理します。名前が秘密・メール内容に当たるグループ（`slog.Group`／`WithGroup`）の中身も丸ごと伏せます。URL エンコードされた形（`access_token%3D…`・`%40`）やキー名の前置（`session_token=…`・`X-Auth-Token: …`）、`Authorization: Basic …`、Google の API キー（`AIza…`）、`code`／`state` クエリ、日本語など非 ASCII のメールアドレスも対象です。書き出し（zip）でも 1 行ずつ同じ処理を通します（古い版が書いたログが残っていても、そのまま外へ出ません）。

| 対象 | 処理 |
|------|------|
| OAuth トークン（アクセス・リフレッシュ・`id_token`）・Client Secret・AI の API キー・MCP トークン・パスワード・`Authorization`／Cookie・認可コード | キー名（`token`・`secret`・`password`・`apikey`・`authorization`・`credential`・`cookie` など）に当たる値は丸ごと `[REDACTED]` に置き換えます。文字列の中に混ざった形（`Bearer …`・`ya29.…`・`1//…`・`GOCSPX-…`・`sk-…`・JWT・`hmcp_…`・`token=…`・JSON の `"access_token":"…"`）も置き換えます |
| メール本文・スニペット・添付（名前を含む）・AI に渡す文脈 | キー名（`body`・`snippet`・`attachment`・`filename`・`html`・`text`・`content`・`prompt` など）に当たる値は `[REDACTED]` |
| **件名・宛先（差出人・To・Cc・Bcc・Reply-To）** | **残しません。** キー名（`subject`・`to`・`cc`・`bcc`・`from`・`recipient`・`email`・`address` など）は `[REDACTED]`、文字列に混ざったメールアドレスは `[email]` に置き換えます |
| 構造体・マップ・スライス | 中身を出さず型名だけにします（`error` と `Stringer` だけ文字列にして処理） |

件名と宛先をログに残さないのは、障害調査に必要な情報（アカウント ID・スレッド ID・エラーコード・件数・時間）で足り、残すと取引先の情報がログ経由で漏れる経路になるためです。panic の値に秘密が混ざっても、同じ処理を通ります。

## 実装の場所

| 機能 | 場所 |
|------|------|
| ログの組み立て・伏せ処理・読み取り・書き出し | `internal/logging` |
| MCP サーバー（待ち受け・トークン検証・ツール） | `internal/mcpserver` |
| 設定・トークンの操作（バインディング） | `internal/app/mcpservice.go`（`MCPService`） |
| MCP が使うアプリの機能（読み取り・下書き） | `internal/app/mcpbackend.go` |
| フロントのエラー送信・ログ操作（バインディング） | `frontend/src/lib/errorReporter.ts`／`internal/app/logservice.go`（`LogService`） |
