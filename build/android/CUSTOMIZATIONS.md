# build/android のテンプレートからの変更点

`build/android/` は Wails v3 の Android テンプレートのコピーで、このリポジトリで管理している。Wails を上げてテンプレートを取り込み直すとき、ここに書いた変更を戻し忘れないよう、**テンプレートから変えた点を 1 行ずつ**記録する（Issue 番号つき）。他の Issue でも、テンプレートのファイル（Java・Gradle・manifest・Taskfile など）を変えたらここへ追記する。

- `app/src/main/java/com/wails/app/SecureStore.java`（新規）: 資格情報の保管を Activity に依存しない static なシングルトンに切り出した。Keystore の鍵の喪失を検出してストアを作り直し、Go へ `key_lost` を返す（#84）
- `app/src/main/java/com/wails/app/WailsBridge.java`: `secureSet`／`secureGet`／`secureDelete` を `SecureStore` への委譲に置き換えた。`securePrefs()`・`cachedSecurePrefs` と `EncryptedSharedPreferences`／`MasterKey`／`SharedPreferences` の import を削除。失敗は `{"ok":false,"error":"<key_lost|failed|empty key>"}` だけを返し、値・例外メッセージを含めない（#84）
- `app/src/main/java/com/wails/app/WailsBridge.java`: `handleMessage`／`handleRuntimeCall` のデバッグログから JS のペイロード本文を外し、長さだけにした（引数に API キーなどが含まれうるため）（#84）
- `app/build.gradle`: `androidx.security:security-crypto` を `1.1.0-alpha06` から安定版 `1.1.0` に変更（#84）
- `app/build.gradle`: `testImplementation 'junit:junit:4.13.2'` と `testOptions.unitTests.returnDefaultValues = true` を追加し、`app/src/test/java/com/wails/app/SecureStoreTest.java`（新規）で `SecureStore` を JVM 単体テストする（#84）
- `app/src/main/java/com/wails/app/WailsJSBridge.java`: `invoke`／`invokeAsync` のデバッグログから JS のペイロード本文を外し、長さだけにした（バインディング呼び出しの引数に API キー・Client Secret が含まれるため）（#84）
- `Taskfile.yml`: `test` タスク（`./gradlew testDebugUnitTest`）を追加。CI の android ジョブが `wails3 task android:test` で呼ぶ（#84）
- `Taskfile.yml`: `compile:go:shared` の `ARCH=amd64` だけ `build/android/scripts/libc-overlay.go` を実行して `go build -modfile=…`（パッチ済みの `modernc.org/libc`。`build/android/libc/amd64.patch`）で作る。`clean` が `build/android/gen` も消す（#83。[docs/environment/android.md §12](../../docs/environment/android.md)）
- `app/src/main/java/com/wails/app/DocumentExporter.java`・`DocumentPaths.java`（新規）: 保存先を選ばせて（`ACTION_CREATE_DOCUMENT`）Go が書いた一時ファイルをストリームコピーする状態機械と、パス・ファイル名の検査。Android に依存せず JVM で単体テストする（`DocumentExporterTest`・`DocumentPathsTest`）（#85）
- `app/src/main/java/com/wails/app/WailsBridge.java`: `documentTempDir`／`documentBegin`／`documentCommit`／`documentAbort`／`documentOpen`／`documentPickerResult`（保存・ファイルを開く）を追加。Go は `go:linkname` で呼び、結果は `hitomado:document` イベントで返す。`java.io.File`／`OutputStream` の import を追加（#85）
- `app/src/main/java/com/wails/app/MainActivity.java`: `launchCreateDocument` と、`onActivityResult` の `CREATE_DOCUMENT_REQUEST`（7005）の分岐を追加（#85）
- `app/src/main/res/xml/file_paths.xml`: 試作（テンプレート）の `cache-path captures/` を外し、`files-path Hitomado/logs/`（ログ）だけを公開する。テンプレートのカメラ撮影（`launchCameraCapture`）はこのアプリでは使わない（#85）
- `app/src/main/java/com/wails/app/MainActivity.java`: エッジ・ツー・エッジ（targetSdk 36 で強制）の safe area として、`applyWindowInsets()` が system bars・display cutout・IME の insets をコンテナ（`main_container`）の padding に当てる。`updateSystemBarIcons()` でライト／ダークに合わせてバーのアイコン色を切り替える（`onConfigurationChanged` でも呼ぶ）。`androidx.core` の `WindowCompat`／`ViewCompat`／`WindowInsetsCompat`／`Insets` の import を追加（#87）
- `app/src/main/java/com/wails/app/MainActivity.java`: 戻るボタンを `OnBackPressedCallback`（`handleBack()`）で受け、`window.hitomadoHandleBack()`（フロントの `frontend/src/lib/androidBack.ts`）を `evaluateJavascript` で呼ぶ。`true` ならフロントが一つ前の画面へ戻したので何もせず、それ以外は WebView の履歴（`canGoBack`）、無ければ `moveTaskToBack(true)`（アプリをバックグラウンドへ）。テンプレートの `onBackPressed()` の上書きは削除（targetSdk 36 では呼ばれない）（#87）
- `app/src/main/res/values/colors.xml`・`values-night/colors.xml`（新規）・`values/themes.xml`: `app_background`（フロントの `--color-bg` のライト／ダークと同じ値）を足し、`statusBarColor`・`navigationBarColor`・`windowBackground` をテンプレートの `wails_background` から `app_background` に変えた（バーの後ろ・起動直後の背景をアプリの背景に揃える）（#87）
- `app/src/main/java/com/wails/app/WailsForegroundService.java`: 削除。前面サービスは使わない（常時表示の通知・Android 15 以降の `dataSync` の時間上限・Play の審査を避け、バックグラウンド同期は WorkManager で行う）。`AndroidManifest.xml` の `<service android:name=".WailsForegroundService">` と、権限 `FOREGROUND_SERVICE`・`FOREGROUND_SERVICE_DATA_SYNC` も削除し、WorkManager が足す `FOREGROUND_SERVICE` は `tools:node="remove"` で取り除く（#88）
- `app/src/main/java/com/wails/app/WailsBridge.java`: `startForegroundService`／`stopForegroundService`／`postNotification` を削除。`secureSet`／`secureGet`／`secureDelete` は新規の `SecretBridge`（Activity 不要。Worker と共有）への委譲にした。`notifyNewMail`／`scheduleSync`／`forgetAccount`／`notificationPermission`／`requestNotificationPermission`／`openNotificationSettings`／`takeOpenRequest` を追加（Go は `go:linkname` で呼ぶ）。`NotificationCompat`・`Notification*` の import を削除（#88）
- `app/src/main/java/com/wails/app/MainActivity.java`: `onCreate` で通知タップの Intent を `OpenRequest` に保持し、`onNewIntent` で保持して Go へ `hitomado:open-thread` を送る（#88）
- `app/src/main/java/com/wails/app/{SyncWorker,SyncScheduler,HeadlessSync,SecretBridge,NewMailNotifier,NotificationPlan,OpenRequest,ReconnectState,SyncOutcome,SyncPlan}.java`（新規）: WorkManager の定期同期（15 分・ネットワーク接続）、Go のヘッドレス同期を呼ぶ JNI 入口、アカウント別チャネル・グループ化・ロック画面で内容を隠す通知、通知タップのディープリンク。`SyncOutcome`・`SyncPlan`・`NotificationPlan`・`OpenRequest`・`SecretBridge` は JVM で単体テストする（#88）
- `app/src/main/res/drawable/ic_stat_mail.xml`（新規）: 通知の小さなアイコン（#88）
- `app/build.gradle`: `androidx.work:work-runtime:2.12.0`（最新安定版。minSdk 24。minSdk 31 で満たす）、`testImplementation 'org.json:json:20240303'` を追加（#88）
- `app/build.gradle`（`android.packaging`）・`scripts/verify-apk.sh`: `jniLibs.useLegacyPackaging = true`・`dex.useLegacyPackaging = true` で `.so` と dex を圧縮して APK に入れる（既定は無圧縮で release APK が約 46MB → 約 17MB）。manifest は `extractNativeLibs="true"` になる（端末上で `.so` を展開）。`verify-apk.sh` に `extractNativeLibs=true`・`libwails.so` と `classes.dex` が Deflate であることの検査を追加（docs/environment/android.md §6.1）
- `scripts/verify-apk.sh`: 権限の許可リストから `FOREGROUND_SERVICE`・`FOREGROUND_SERVICE_DATA_SYNC` を外し、WorkManager の `WAKE_LOCK`・`RECEIVE_BOOT_COMPLETED` を足した。`WailsForegroundService` が manifest に残っていないことの検査を追加（#88）
- `app/src/main/java/com/wails/app/MainActivity.java`: `WebViewClient` に `onRenderProcessGone` を追加（テンプレートには無く、未処理のレンダラ落ちで `Render process crash wasn't handled` となりアプリ全体が終了していた）。`true` を返し、落ちた WebView を `destroy` して新しい WebView を作り直し（`recreateWebView`）、`setupWebView`・`loadApplication` でブリッジ（JS インターフェース・`WailsBridge` の WebView 参照）をつなぎ直す。直近 5 分に 3 回（`RecoveryBudget`）を超えたら `showFatalError`（エラー画面と「アプリを終了」）。ログの文言はクラッシュと OS による終了で分ける（`RenderGoneReason`）（#90）
- `app/src/main/java/com/wails/app/MainActivity.java`: `WebViewClient.onReceivedError` を追加。メインフレーム（アプリの URL）の読み込みが失敗したとき（Wails の Go 側は準備が 10 秒で終わらないと最初の `/index.html` を捨てる）、3 秒後に読み直す。直近 5 分に 6 回（`RecoveryBudget`）を超えたら `showFatalError`。`loadApplication` の URL は `appUrl()` に切り出した（#90）
- `app/src/main/java/com/wails/app/{RecoveryBudget,RenderGoneReason}.java`（新規）・`app/src/test/java/com/wails/app/{RecoveryBudgetTest,RenderGoneReasonTest}.java`（新規）・`app/src/main/res/values/{ids,strings}.xml`: 再試行の上限（窓の中の回数）、レンダラが消えた理由のログ文言、エラー画面の文言と id（#90）
- `Taskfile.yml`: `e2e:apk`（`E2E=true` でビルドタグ `e2e` を足した debug APK を `bin/hitomado-e2e.apk` に作る。`PRODUCTION=true` との併用は `build` の precondition で拒否）・`e2e:run`（`e2e/run.sh`）を追加。`compile:go:shared` の `BUILD_FLAGS` は `E2E=true` のときだけ `,e2e` を足す（#90）
- `e2e/{run.sh,ui.py}`（新規）: adb と UI Automator の画面ダンプで「起動 → 一覧 → 返信下書き → レンダラ kill からの復帰」を検証する。`scripts/verify-apk.sh`: `libwails.so` に E2E の印（`internal/e2e.Marker`）が無いことの検査を追加（#90）
- `app/build.gradle`（`minSdk` 21 → 31）・`Taskfile.yml`（`MIN_SDK` 21 → 31。NDK の clang の API レベル）・`scripts/verify-apk.sh`（`minSdkVersion=31` を検査）: 最低対応を Android 12（API 31）にした（理由は docs/environment/android.md §3）。これに合わせて自前のコード（`SecureStore`・`NewMailNotifier`・`MainActivity` の `onRenderProcessGone`）の API 23／26 未満の分岐と `@RequiresApi` を外した。**テンプレート由来の `SDK_INT` の分岐（`WailsBridge.java` と `MainActivity.java` の `SDK_INT >= Q`）は、minSdk 31 では結果が決まっているものも、テンプレートとの差分を膨らませないため残した**
- `app/src/main/res/values/colors.xml`・`values-night/colors.xml`・`values/themes.xml`: テンプレートの青（`wails_blue`・`wails_blue_dark`）と未使用の `wails_background` を削除し、Material テーマの `colorPrimary`・`colorPrimaryVariant` を `app_accent`（フロントの `--accent` のライト `#050505`／ダーク `#F5F5F4`）、`colorOnPrimary` を `app_background` に変えた（独自の青を使わない。#139）
